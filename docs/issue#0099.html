Issue #0099 — Backend failure classification and side-effect observation — 2026-08-05

Design Decisions

Classify by machine code

Routing classes are derived from controlled error codes. Upstream natural-language class hints are ignored, and MODEL_NOT_FOUND remains configuration while temporary capacity remains retryable.

Fail closed on effect uncertainty

Read-only declared effects may be clean; write or external effects are confirmed; missing effect, empty evidence, parse failure, unknown vendor events, and stream gaps remain possible or unknown.

Keep transport fallback inside one Attempt

Persistent-to-spawn fallback reuses the same result promise and backend turn boundary. It records fallback metadata without creating a second model Attempt.

Redact at both normalization and persistence boundaries

Vendor and parsed events, metadata, structured components, diagnostics, fallback logs, and transcript append paths use the shared redactor. Structured sensitive fields become [REDACTED]; ordinary file paths remain available.

Deviations

Local waiver remains explicit

The evidence is in-process and fixture-backed. No real Provider/Codex, packaged Tauri, cross-process lock/fsync/crash-restart, or real stream interruption claim is made.

Review capped at two rounds

The first and second read-only review findings were fixed. A third review was not started because the loop requires a maximum of two review rounds; the final state was checked with independent tests and a targeted static audit.

Tradeoffs

Conservative redaction over raw diagnostic fidelity

Stable codes, phases, effect states, and ordinary paths remain available, while likely credentials, prompts, tokens, keys, environment values, and nested sensitive fields are removed before persistence.
