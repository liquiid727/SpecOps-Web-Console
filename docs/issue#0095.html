Implementation Notes

Issue #0095 — Priority Route state, CRUD, and schema v8 — 2026-08-05

Design Decisions

Keep Route storage separate from resolution

Routes persist ordered, unique candidate IDs and the technical fallback flag. Missing Deployment IDs remain valid stored candidates; eligibility and selection remain issue 096 concerns.

Preserve recovery boundaries

v7 migration creates a first-write backup, does not overwrite an existing backup, and leaves the source recoverable when migration writing fails. Readonly migration stays in memory.

Deviations

Invalid references are sanitized during migration

Malformed routes, duplicate IDs, invalid global/workspace bindings, duplicate workspace bindings, and missing session Route references are removed while valid historical Route data remains.

Tradeoffs

Rollback is explicit around state saves

Route and binding mutations restore their in-memory snapshot when persistence fails. API tests also reload a fresh JSON repository after server close to prove successful writes are durable.

Open Questions

External environments

Packaged-host, cross-process, real external Provider/engine, and browser behavior remain outside this local feature gate. No evidence is inferred for those environments.
