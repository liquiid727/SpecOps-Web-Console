Design Decisions

One registry decision boundary

Enablement errors and exclusion/eligibility calculation stay in the deployment registry; the API supplies Provider, Profile, catalog, capability, and SecretStatus context.

Deviations

Process-local concurrency scope

POST/PATCH/DELETE mutations are serialized inside one application process. Cross-process locking remains an explicit unverified boundary rather than an implied property.

Tradeoffs

Disabled unknown deployments remain inspectable

Capability or catalog unavailability can be stored disabled and summarized without claiming eligibility, while enabled mutations fail with stable errors.
