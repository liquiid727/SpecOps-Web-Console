Implementation Notes

Issue #0094 — Preserve legacy model resolution and Deployment history compatibility — 2026-08-05

Design Decisions

One legacy resolution boundary

The resolver owns active-model, launch-config, and profile-default precedence. A no-route result carries the typed legacy resolution; it never fabricates a Deployment identity.

Route binding remains authoritative

When a route is bound and has no executable candidate, resolution remains a route failure. It does not silently fall back to the legacy profile/model path.

Deviations

Fork runtime tokens are not inherited

A fork retains model and backend identity needed for history and future execution, while child chat/terminal runtime resume tokens are cleared so a fork does not accidentally continue the parent process context.

Tradeoffs

History snapshots are immutable records

Deployment archive changes future eligibility, while frozen execution task/attempt records retain provider, profile, model, and route data. The regression reopens the disk repository after archive to verify that history does not re-resolve live registry state.

Open Questions

Environment-specific verification

Real external Provider, packaged Tauri, and platform/browser behavior remain outside CLI-GUI-029's feature-specific Test Spec and require a separate approved environment if release evidence is later needed.
