Implementation Notes

Issue #0096 — Pure Route resolver precedence and exclusions — 2026-08-05

Design Decisions

Resolve only supplied summaries

The resolver remains a pure boundary: it consumes Route bindings and Deployment summaries, preserves source provenance and candidate order, and never performs I/O or runtime work.

Fixed targets fail closed

An explicit fixed Deployment must belong to the final Route and be eligible. Missing, non-member, empty, or excluded targets make the result non-sendable instead of silently selecting another candidate.

Deviations

Public exclusion mapping

Deployment summary eligibility and exclusion codes are mapped to the existing public RouteExclusionCode union; no new public error code was introduced.

Tradeoffs

Preserve all candidate evidence

Executable candidates are filtered without reordering, while every candidate retains its original position and all applicable exclusion reasons in stable order.

Open Questions

Downstream wiring

API/session/preflight and send-time behavior remain issue 097. Packaged-host, cross-process, external Provider/engine, and browser behavior are not inferred from this pure-function gate.
