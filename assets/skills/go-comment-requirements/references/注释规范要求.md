# 注释规范要求

## 0. 目标与原则

目标：

- 让新同学在 30 分钟内读懂模块边界与关键语义
- 让线上事故复盘能快速定位：状态机、并发、幂等、一致性与失败策略
- 让 godoc / pkg.go.dev / IDE 能自动生成清晰文档

核心原则：

- 注释解释 Why / Contract / Invariants / Failure modes，避免复述代码
- 导出符号（exported）必须注释
- 状态机、强一致门禁、并发语义必须写清楚

## 1. 强制规范（团队必须遵守）

### 1.1 导出符号注释规则

导出符号（type / func / const / var，只要首字母大写）必须有注释。

- 注释第一句必须以符号名开头（GoDoc 规则）
- 第一段一句话说明“是什么”
- 之后用小节说明：Guarantees / Requires / Errors / Concurrency / Side effects

✅ 推荐结构（固定模板）：

```go
// CreateSession creates a new session binding user -> instance.
//
// Guarantees:
//   - At most one active session per user.
//   - Allocation decision is persisted in PostgreSQL within a single transaction.
//
// Requires:
//   - caller must pass validated region/isp constraints.
//
// Errors:
//   - ErrInstanceNotAvailable when no instance can be allocated.
//   - ErrDuplicateSession when user already has an active session.
//
// Concurrency:
//   - Safe for concurrent calls.
func CreateSession(ctx context.Context, userID int64, region, isp string) (*Session, error) {}
```

## 2. 包级注释（doc.go 必须有）

每个核心包（尤其是 connection / session / scheduler / allocator / provider）必须有 doc.go。

模板：

```go
// Package session manages the user connection lifecycle.
//
// Responsibilities:
//   - lock instance (strong gate)
//   - track session state machine
//   - persist session facts in PostgreSQL
//
// Out of scope:
//   - scheduling policy (handled by scheduler)
//   - instance health reconciliation (handled by health manager)
//
// Source of truth:
//   - PostgreSQL is authoritative for session allocation and one-time credential usage.
package session
```

## 3. 状态机注释（强制）

### 3.1 Session 状态机（示例模板）

在 state_machine.go 或 status.go 里写清楚：

```go
// Status represents the session lifecycle state.
//
// State machine:
//
//   connected -> grace -> stopping -> stopped
//
// Invariants:
//   - Only one active session per user at any time.
//   - stopped is terminal.
//
// Illegal transitions MUST be rejected and logged with reason.
type Status string
```

### 3.2 Instance 状态机（示例模板）

```go
// InstanceState represents allocation/health state of an instance.
//
// Allocation gate states:
//   free -> leased -> recycling -> free
//
// Quarantine:
//   - quarantined instances are never schedulable until explicitly released.
//
// Source of truth:
//   - PostgreSQL for allocation gate
//   - runtime cache is advisory only
type InstanceState string
```

## 4. 并发与幂等注释（强制）

任何涉及 Close / Release / Stop / Commit / Consume token 的函数必须写清楚：

- 是否可重复调用（幂等）
- 并发安全性（goroutine safe / needs external lock）
- 竞争时的行为（first-wins / last-wins / CAS）

模板：

```go
// Close terminates a session and releases its instance.
//
// Idempotency:
//   - Safe to call multiple times; only the first call performs release.
//
// Concurrency:
//   - Safe for concurrent calls; uses DB transaction + row lock to ensure first-wins.
//
// Side effects:
//   - marks session as stopping/stopped
//   - enqueues release command to a background worker
func (s *Service) Close(ctx context.Context, sessionID int64) error {}
```

## 5. 一次性凭证 / token / 连接授权注释（强制）

你们最关键的坑在这里：URL + room_id 泄露、残留可重连、无法计时。

所有与凭证相关的结构 / 函数必须写清楚：

- 最终判定在哪里（PG）
- 何时消费（consume）
- 过期策略
- 重放攻击处理

模板：

```go
// OneTimeCredential is a single-use connection authorization.
//
// Security contract:
//   - Must be validated AND consumed server-side before enabling media connection.
//   - Consumption is atomic in PostgreSQL (unique + status transition).
//
// Replay protection:
//   - A consumed credential MUST never be accepted again.
//   - Expired credential MUST be rejected even if never consumed.
type OneTimeCredential struct {
    Token     string
    RoomID    string
    ExpiresAt time.Time
}
```

函数模板：

```go
// ConsumeCredential validates and consumes a one-time credential.
//
// Guarantees:
//   - Exactly-once consumption (first-wins).
//   - Strong consistency: PostgreSQL is the source of truth.
//
// Errors:
//   - ErrCredentialExpired
//   - ErrCredentialConsumed
//   - ErrCredentialInvalidSignature
func (s *AuthService) ConsumeCredential(ctx context.Context, token string) (*CredentialClaims, error) {}
```

## 6. 错误码与业务语义（强制）

### 6.1 错误变量必须注释（尤其要标 HTTP 映射）

模板：

```go
// ErrDuplicateSession indicates the user already has an active session.
// It should be translated to HTTP 409 Conflict.
var ErrDuplicateSession = errors.New("duplicate session")
```

### 6.2 “可重试”也要明确

```go
// ErrProviderTemporary indicates a transient provider failure.
// Caller MAY retry with backoff.
var ErrProviderTemporary = errors.New("provider temporary failure")
```

## 7. 数据库模型与约束注释（强制）

所有映射到表的 model 都要写清楚：

- 关键索引 / 唯一约束
- 强一致门禁字段
- “最终事实来源”

模板：

```go
// SessionModel maps to `sessions` table.
//
// DB constraints:
//   - unique(user_id) WHERE status != 'stopped'  (at most one active session)
//   - index(instance_id)
//   - index(updated_at)
//
// Consistency:
//   - PostgreSQL is authoritative for allocation gate and billing facts.
type SessionModel struct {}
```

## 8. RPC / API Handler 注释（推荐强制）

任何对外 API（包括 internal）建议写清楚：

- 业务语义
- 幂等性
- 超时建议
- 失败返回

模板：

```go
// POST /v1/sessions allocates an instance and returns a connection offer.
//
// Idempotency:
//   - NOT idempotent unless client provides idempotency key.
//
// Timeout:
//   - server enforces 5s for scheduling decision, 10s for credential issuance.
func (h *Handler) CreateSession(w http.ResponseWriter, r *http.Request) {}
```

## 9. 日志注释（推荐）

关键路径建议在注释里标清楚要打哪些字段（方便统一日志规范）。

模板：

```go
// Logging:
//   - request_id, user_id, session_id, instance_id, region, isp, error_code
```

## 10. 禁止事项（踩坑清单）

禁止写：

- 复述代码的废话注释：`// set status`、`// update db`
- 中英夹杂、缩写不解释
- “TODO: optimize” 这种无意义 TODO（必须写清楚原因与入口）

必须写：

- 状态机与不变量
- 并发语义
- 幂等 / 重试语义
- 强一致边界（PG / Redis / cache 谁是真相）

## 11. PR 检查清单（可直接贴到 PR 模板）

- 所有 exported 符号都有 GoDoc 注释（首句以名字开头）
- 涉及 session / instance / token 的代码，注释写清：状态机 / 不变量 / 一致性来源
- Close / Release / Consume 等关键函数写清：并发安全 + 幂等
- 错误变量标明：业务含义 + HTTP 映射 + 是否可重试
- DB model 注释列出：关键约束 / 索引 / 强一致门禁字段
