# Go 注释规范要求

## 目标

统一执行项目注释契约，让代码评审与线上复盘可以快速理解模块边界、不变量、一致性约束与失败语义。

## 使用流程

1. 先阅读 `references/注释规范要求.md`，以此为唯一权威规范。
2. 识别本次变更的 Go 构件，并映射到“必写注释类别”。
3. 按 GoDoc 优先原则补齐或更新注释，重点写清契约与边界。
4. 对关键路径专项检查：状态机、幂等、并发、一致性、凭证安全、DB 约束。
5. 提交前执行 PR 注释检查清单。

## 必写注释类别

- 导出符号：所有导出 `type/func/const/var` 必须注释，首句以符号名开头。
- 包级注释：核心包补 `doc.go`，明确职责、边界（out-of-scope）与事实来源（source of truth）。
- 状态机：写清状态迁移、不变量、非法迁移处理与终态定义。
- 并发与幂等：对 `Close/Release/Stop/Commit/Consume` 一类函数说明幂等性、并发安全、竞争策略、副作用。
- 一次性凭证/token：写清校验与消费时机、过期策略、重放防护、PG 强一致判定来源。
- 错误变量：写清业务语义、HTTP 映射、是否可重试。
- DB 模型：写清关键约束、索引、强一致门禁字段、最终事实来源。
- API Handler：写清业务语义、幂等性、超时建议、失败返回约定。

## 写作规则

- 注释要解释 Why / Contract / Invariants / Failure modes，避免复述实现步骤。
- 避免中英混乱与未解释缩写，术语表达保持一致。
- 禁止无意义 TODO；确需 TODO 时必须写明原因与落地点。
- 行为变更必须同步更新注释，保证注释与代码语义一致。

## PR 门禁

结束任务前，必须核对 `references/注释规范要求.md` 的 `11. PR 检查清单`。
