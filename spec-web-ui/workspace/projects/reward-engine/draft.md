# Reward Feature Spec Draft

## 背景

积分奖励中心需要统一活动投放、发奖和回溯追踪。

## 目标

支持一次奖励活动从配置、触发到发放结果追踪的闭环。

## 非目标

本次不包含积分商城的商品核销能力。

## 用户角色

- 运营
- 用户
- 奖励引擎

## User Flow

1. 运营创建奖励活动
2. 用户完成触发行为
3. 系统发放奖励并反馈结果

## System Flow

1. 系统校验活动状态和幂等
2. 系统写入发奖记录
3. 系统输出日志、指标和 trace

## API 草案

- POST /rewards/activities
- POST /rewards/issue

## 状态机

活动支持草稿、发布中、已停止三种状态。

## 数据模型

- RewardActivity
- RewardIssueRecord

## 业务规则

- 同一触发事件只能发奖一次
- 活动过期后不允许继续发奖

## 异常场景

- 发奖超时
- 幂等冲突

## 测试场景

- 正常发奖
- 重复请求拦截

## 运营/后台配置

- 活动状态切换
- 发奖开关

## 指标与日志

- 发奖成功率
- trace_id

## 待确认问题

- 发奖失败是否允许人工补发
