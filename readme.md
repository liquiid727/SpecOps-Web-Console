# 使用说明

## Quick Start


简单介绍



面向工程和业务系统开发的 Spec-Driven AI IDE

核心：

 不是让 AI 如何帮助写代码，而是让需求、spec、agent、测试、接口、CI、报告全部围绕同一套工程语义进行流转


他做什么/负责什么

* 需求的结构化-
* spec-draft 管理
* agent 模板管理
* 流程编排
* 测试生成
* 报告展示
* 上下文约束

  实际上写代码，还是依靠

  - codex
  - cladude code

  我只是不希望他跑的太偏，导致我完全看不懂，

围绕的核心问题

- feature 如何形成进入 spec
- agent 应该查看哪些上下文
- 接口生成后如何进入 bruno
- 自动化场景测试，如何展示场景和链路
- 本次改动对应什么 spec version


为什么做呢？
* 需求输入不稳定
* spec 格式不稳定
* 上下文散落
* agent 角色混乱
* 测试没有固定入口
* 生成结果不可追溯
* 每次对话都要重新解释很多的工程规则
