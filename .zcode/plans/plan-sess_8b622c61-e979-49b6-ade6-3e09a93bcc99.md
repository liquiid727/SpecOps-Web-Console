实现 `cli-gui` 开发环境的自动端口切换，避免端口冲突时把 `/api` 请求转发到其他项目。

1. 调整开发启动入口
   - 将 `cli-gui/package.json` 的 `dev` 从 `concurrently` 改为使用现有的 `scripts/dev-status.ts` 监督器。
   - 保留 `dev:server` 和 `dev:client`，供 Tauri 或单独调试场景继续使用。

2. 在 `scripts/dev-status.ts` 集中选择端口
   - 使用 Node 标准库 `net` 检测 loopback 端口是否可用，不增加依赖。
   - 默认优先使用 GUI `3000`、后端 `3001`；如果被占用，则从对应首选端口开始递增选择下一个可用端口。
   - 保证 GUI 和后端不会选择同一个端口。
   - 支持已有环境变量作为首选值：`SPECOS_GUI_PORT` 用于 GUI，`SPECOS_API_PORT` 或后端现有的 `PORT` 用于 API；发生冲突时仍自动递增。
   - 用选出的端口生成健康检查地址、WebSocket 地址和最终启动 banner，打印实际可访问的 GUI URL。
   - 启动子进程时传递统一环境：`SPECOS_GUI_PORT`、`SPECOS_API_PORT` 和后端 `PORT`，确保前后端使用同一组选定端口。

3. 让 Vite 使用监督器传入的端口
   - 修改 `cli-gui/vite.config.ts`，读取 `SPECOS_GUI_PORT` 和 `SPECOS_API_PORT`。
   - `/api` 与 `/ws` 代理目标都使用动态 API 端口。
   - 保留 `strictPort: true`，因为端口已由监督器预先选择；这样出现极少见的启动竞态时会明确失败，不会静默落到错误服务。
   - 未通过监督器启动时继续回落到原来的 `3000`/`3001` 默认值，避免影响 Tauri 配置和已有单独启动方式。

4. 让后端授权接受动态 GUI 来源
   - 修改 `server/index.ts`，读取 `SPECOS_GUI_PORT`，将动态 GUI origin 加入 `allowedOrigins`。
   - 保留默认 `3000` 回退值以及后端自身端口的现有安全校验，确保动态端口不会绕过 Host/Origin/CSRF 授权。

5. 增加回归测试与文档
   - 在 `scripts/dev-status.test.ts` 覆盖：端口被占用时选择下一个端口、GUI/API 端口不重复、动态 URL/banner 和子进程环境配置。
   - 更新 `cli-gui/README.md`，说明默认端口、冲突时自动切换，以及应使用启动 banner 中打印的 GUI 地址。
   - 不修改客户端 API/WebSocket 相对路径，保持浏览器始终通过同源 Vite 代理访问后端。

6. 验证
   - 运行 `npm --prefix cli-gui run test`。
   - 运行 `npm --prefix cli-gui run build`。
   - 在当前存在端口占用的环境中执行一次开发启动烟测，确认不会再请求 NN 加速器的 Next.js `/api/state`，并确认页面能加载状态数据。
