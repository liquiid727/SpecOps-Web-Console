## cli-gui 启动失败直接报错（issue-018，用户截图反馈）

用户截图：CLI 进程（circular-dependency 崩溃）启动后，会话只显示「已停止/Stopped」，真实失败原因完全看不到。
根因：
- `server/orchestrator.ts` `finishExit()`：终端 PTY 进程退出时**无论退出码一律报 `stopped`**；只有 `spawn()` 同步抛错才走 `error` 态。进程 spawn 成功但立即崩溃（非 0 退出）→ 被误判为「已停止」，且不写 `session.error`。
- 客户端即使 `runtimeStatus==="error"` 也没有醒目错误提示，仅显示「已停止」标签。

修复：
- `server/orchestrator.ts`：terminal worker 新增 `recentOutput`（环形缓冲 8KB）+ `terminatedByUs` 标记；`finishExit()` 在 `exitCode !== 0 && !terminatedByUs` 时改报 `error` 态，并把崩溃信息（`exited with code N` + 最近 PTY 输出）写入 `error` 事件与 `session.error`；主动 `stop()` 标记 `terminatedByUs` 避免误报。
- `server/ports.ts`：`onRuntimeStatus` 的 `extra` 增加 `errorMessage?: string`。
- `server/application.ts`：`onRuntimeStatus` 的 `error` 分支用 `extra.errorMessage` 填充 `session.error.message`。
- `client/transcript-display.ts`：`deriveSessionLifecycleStatus` 现在识别事件流中的 `error` 事件 → 顶部状态条显示 `failed`。
- `client/components/ChatView.tsx`：新增 `session-error-banner`（role=alert，展示 `session.error.message` +「恢复」按钮）；头部 `Badge` 改用 `statusLabel` 本地化文案（不再显示 raw `error`）。
- `client/i18n.tsx`：新增 `sessionStartFailedTitle`（EN/ZH）、`sessionStartFailedDetail`（EN/ZH）。
- `client/styles/qoder.css`：新增 `.session-error-banner` 样式。
- `server/orchestrator.test.ts`：新增 describe「terminal session crash reporting」，覆盖「非 0 退出→error 且捕获 stderr」「干净退出/主动 stop→stopped 不误报 error」。

验证：服务端 tsc 0 错误；客户端 tsc 仅剩 9 个既有无关错误；`vitest run` 240 测试全过；`npm run build` 成功，`dist-server`/`dist` 含本次改动。

注意（非本次范围）：`orchestrator.stop()` 的 terminal 分支只 `broadcastTerminal(stopped)` 而**未调 `callbacks.onRuntimeStatus("stopped")`**，因此手动停止的会话依赖周期 `GET /api/state` 刷新才能拿到 stopped（原行为，未改）。
